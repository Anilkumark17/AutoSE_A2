# T2 — Local feature: collapsible admonitions

## Spec (sent to the agent verbatim)

```text
The admonition extension should also accept a collapsible form. A block that
starts with `???` instead of `!!!` uses the same class names and title rules
as `!!!` (the capitalized default title when no title is given, and no title
element when the quoted title is empty), but the outer element is `<details>`
and the title is a `<summary class="admonition-title">` rather than a paragraph.
Indented body content is parsed as Markdown, including emphasis, lists, and
nested admonitions. A later indented block stays inside the same disclosure,
just as a later indented block stays inside an `!!!` admonition. `!!!` blocks
are unchanged. Both markers may appear in the same document.
```

## Hidden acceptance tests

`experiment/acceptance_tests/test_T2.py` (4 tests): a `???` block with emphasis
in the body; default title, empty title, and an `!!!` block still rendered as
a `div`; a second indented paragraph stays inside the same `<details>`; a list
inside the disclosure.

## Design-fit checks (scored from the diff, 1 point each)

1. **Stays in its module:** the feature is implemented in
   `markdown/extensions/admonition.py` (tests aside). No core pipeline module
   (`core.py`, `blockparser.py`, `blockprocessors.py`, `inlinepatterns.py`,
   `treeprocessors.py`, `preprocessors.py`, `postprocessors.py`, `serializers.py`,
   `util.py`) is edited.
2. **Same processor:** `???` is handled by the existing `AdmonitionProcessor`
   registered as `admonition`, not by a new preprocessor, postprocessor, or a
   regex substitution over the serialized HTML.
3. **Continuation still works through the processor:** indented blocks that follow
   the disclosure are attached by the processor's existing sibling logic, which
   recognises the `<details>` element. A second, independent pass that wraps
   already-rendered HTML does not count.
