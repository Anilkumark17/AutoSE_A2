# T1 — Bug fix: headings with no usable id text

## Spec (sent to the agent verbatim)

```text
Bug: with the toc extension, a heading whose text has no characters that can
form an id (for example `# !!!` or `# ???`) is rendered as `<h1 id="">!!!</h1>`.
Its table-of-contents link points at `#`, and `md.toc_tokens` reports an empty id.
Every such heading must get a non-empty id, unique in the document, using the
same `_1`, `_2`, ... numbering already used for duplicate ids. `# !!!` followed
by `## ???` gets `_1` and `_2`, and the TOC links and `toc_tokens` use those ids.
An id already used on any element must not be reused. Ordinary heading ids
must not change. Fix the bug.
```

## Injected bug (not shown to the agent)

In `markdown/extensions/toc.py`, `TocTreeprocessor.run`, a heading with no
pre-existing `id` is slugified and then passed to `unique()` only when the slug
is non-empty. An empty slug is written straight into the `id` attribute, so
`unique()` never sees it. `unique()` itself is unchanged, and its unit tests
still pass. Restoring the original one-line call
`el.attrib["id"] = unique(self.slugify(...), used_ids)` fixes the behaviour.
Editing only `unique()` does not, because the empty slug never reaches it.
The full existing suite still passes with the bug (1077 passed, 0 failed, 52 skipped).

## Hidden acceptance tests

`experiment/acceptance_tests/test_T1.py` (4 tests): one empty-slug heading;
two empty-slug headings at different levels, including nested `toc_tokens`;
ordinary and duplicate headings unchanged, plus an id already taken via
`attr_list` so the empty heading must not reuse it; a second `convert` on the
same `Markdown` instance numbers from `_1` again.

## Design-fit checks (scored from the diff, 1 point each)

1. **Right place:** empty slugs go through `unique()` in `TocTreeprocessor.run`
   (the guard that skips `unique()` for an empty slug is gone). A change only
   inside `slugify` or `unique`, or a workaround in the serializer, does not count.
2. **No collateral change:** `slugify`, `unique`, and `TocExtension` config keep
   their signatures, and no source file other than `markdown/extensions/toc.py`
   is modified (tests aside).
3. **Regression test:** a test for the empty-id case is added under `tests/`,
   using `markdown.test_tools.TestCase` or the existing `toc` test style.
