# T3 — Cross-component change: a `tasklist` extension

## Spec (sent to the agent verbatim)

```text
Add a built-in extension `tasklist`. A bullet or numbered item whose text
starts with `[ ]`, `[x]`, or `[X]` plus a space is a task: remove the marker,
insert a disabled checkbox (`type="checkbox"`, also `checked` for `[x]`/`[X]`)
at the start of the item content, and set the `li` class from `item_class`
(default `task-list-item`). In a loose list the checkbox starts the first
paragraph. Nested lists work, and Markdown in the rest of the item is rendered.
Non-matching items, and `[x]` outside a list item, stay unchanged. Load it like
other built-ins (`tasklist`, `markdown.extensions.tasklist`, or `TaskListExtension`,
options via `extension_configs` or keywords) in both `html` and `xhtml`.
```

## Hidden acceptance tests

`experiment/acceptance_tests/test_T3.py` (4 tests): tight bullet and ordered
lists loaded by the `tasklist` entry point and by the dotted module path;
a loose item, a nested list, and emphasis in the item text; a document with
no task markers (and a `[x]` that is not a marker) identical to rendering
without the extension; `item_class` via a `TaskListExtension` keyword and via
`extension_configs`, with `output_format='html'` (no self-closing `/>`) and
`output_format='xhtml'` (empty checkbox serialized with `/>`).

The short name `tasklist` is resolved from installed entry points, so the
package under test has to be installed before this file is run.

## Design-fit checks (scored from the diff, 1 point each)

1. **Extension contract:** `markdown/extensions/tasklist.py` defines
   `TaskListExtension(Extension)` with options in `self.config`
   (`[default, description]`), an `extendMarkdown(md)` override, and a
   module-level `makeExtension(**kwargs)`.
2. **Registered like the built-ins:** the short name is an entry point
   `tasklist = 'markdown.extensions.tasklist:TaskListExtension'` under
   `[project.entry-points.'markdown.extensions']` in `pyproject.toml`, not a
   special case in `core.py` / `build_extension`.
3. **Plugs in through a registry:** the checkbox is produced by a
   `Treeprocessor`, `BlockProcessor`, or inline processor registered on `md`.
   No core pipeline module is edited, and no third-party dependency is added.
